# LED Canvas

벽면 사진 한 장 위에 LED 캐비닛을 **실측 스케일**로 배치하는 브라우저 도구.

사진에 함께 찍힌 기준 사각형(A4 용지 등)으로 호모그래피를 구해 사진의 원근을 펴고,
그 평면 위에서 cm 단위로 LED 레이어를 배치·계산한다.

- 스택: Vite 8 + React 19 + TypeScript + zustand, 런타임 의존성 없음(순수 브라우저 API)
- 사진은 브라우저 안에서만 처리되고 서버로 전송되지 않는다

## 실행

```bash
npm install
```

```bash
npm run dev
```

`http://localhost:4320`. 빌드는 `npm run build`, 로직 테스트는 `npm test`.

## 사용 흐름

1. **배경사진** — 벽면 사진 1장. 벽과 같은 평면에 A4 용지를 붙여 함께 촬영.
2. **스케일 보정** — A4를 자동 인식(수동 지정도 가능). 네 모서리를 드래그해 정밀 조정.
3. **LED 배치** — 캐비닛 단위로 레이어를 추가·이동·리사이즈. 캐비닛 수·해상도·실측 크기 자동 산출.

## 설계 결정

### 사진은 브라우저를 벗어나지 않는다

기준 용지 인식은 전부 로컬에서 수행한다. 참조 구현은 외부 Workers AI 엔드포인트로 원본
사진을 먼저 업로드했는데, 고지가 없었고 **정확도도 로컬 계산보다 나빴다**(합성 테스트에서
벽면 크기 오차 26% vs 로컬 0%). 네트워크 왕복 1.2초와 실패 시 15초 타임아웃도 함께 사라졌다.

### A4 방향을 판별한다

기준 사각형을 21 × 29.7 cm로 고정하면 용지를 눕혀 붙인 사진에서 가로/세로가 뒤바뀐 채
조용히 계산된다(테스트 결과 160 × 120 cm 벽이 114 × 172 cm로). `resolveA4Size()`가 검출된
사각형의 변 길이로 방향을 정한다.

### 모서리는 점이 아니라 선으로 구한다

기준 사각형은 사진에서 작고, 호모그래피는 그 작은 사각형에서 사진 전체로 외삽된다.
따라서 모서리 오차가 증폭된다 — 실측에서 A4의 2 px 뒤틀림이 벽면 3% 오차로 커졌다.
`refineQuad.ts`는 네 변에 각각 최소제곱 직선을 피팅해 교점으로 모서리를 다시 구한다.
변마다 수백 개의 경계 픽셀이 평균되므로 서브픽셀 정밀도가 나온다.

| 합성 테스트 (정답 160 × 120 cm) | 정밀화 전 | 정밀화 후 |
|---|---|---|
| 가로 A4 | +3.09% | **+0.34%** |
| 세로 A4 | +3.41% | **+0.48%** |

### 수평은 사진이 정하고, 기준 용지는 크기만 정한다

정면 보정은 기준 사각형의 변을 수평·수직으로 만드는 변환이다. 그래서 A4를 벽에 조금이라도
비뚤게 붙이면 **사진 전체가 그 각도만큼 돌아간다**. 실제 현장 사진에서 1.6° 기울게 붙은 A4가
벽면 전체를 1.9° 회전시켰다("앱이 사진을 돌려버렸다"로 보이는 증상).

기준 용지는 스케일과 원근에는 신뢰할 만하지만 "어느 쪽이 위인가"에는 그렇지 않다. 그래서
`calibrate.ts`의 `levelToPhoto()`가 사진의 수평 중심선이 결과에서도 수평이 되도록 역회전을
적용한다. 회전은 강체 변환이라 거리·면적·호모그래피의 원근 행은 전혀 바뀌지 않는다.

### 작업 캔버스는 벽 전체를 보여준다

프레임 비율을 고정하지 않고 정면 보정된 벽면 전체를 contain으로 맞춘다. 참조 구현은
16:9 프레임에 cover로 채워 4:3 사진의 25%, 세로 사진의 58%를 잘라냈고, 잘린 영역에
배치된 레이어는 보이지도 닿지도 않았다.

### 무거운 작업에 `requestAnimationFrame`을 쓰지 않는다

애니메이션 프레임은 탭이 백그라운드면 실행되지 않는다. 참조 구현은 인식을 rAF 안에서
시작해, 사진을 올린 뒤 다른 탭을 보고 오면 "인식 중…"에서 영구히 멈췄다.

### 오브젝트 URL은 스토어가 소유한다

배경사진과 레이어 콘텐츠의 blob URL을 교체·삭제·초기화 시점에 `revokeObjectURL`한다.

## 인쇄

편집 화면의 **인쇄 · PDF** 버튼 → A3 가로 1장.

배치하고 이미지를 올린 그 상태 + 레이어 상세표 + 합계가 한 장에 들어간다.

### 화면과 인쇄가 같은 컴포넌트를 쓴다

한동안 인쇄는 캔버스에 장면을 **다시 그리는 별도 코드**였다. 같은 그림을 두 벌 구현해 두니
테두리 색, 라벨, 치수, 잘림 처리가 계속 어긋났고, 한쪽을 고칠 때마다 다른 차이가 드러났다.
지금은 편집 화면과 인쇄가 모두 `WorkspaceView` 하나를 렌더링한다 — 편집 쪽은 드래그 핸들을
붙이고, 인쇄 쪽은 종이 크기를 넘길 뿐이다. 구조적으로 어긋날 수 없다.

크기는 px로 넘긴다. CSS가 1mm를 정확히 96/25.4 px로 정의하므로, px로 잡은 레이아웃이
종이에서 의도한 mm로 나온다.

### 인쇄 시 CSS

브라우저는 기본적으로 배경 이미지를 인쇄에서 빼므로 `print-color-adjust: exact`가 필요하다.
미리보기용 `zoom`은 인쇄에서 1로 되돌린다. 미리보기는 `createPortal`로 `.app` 바깥에
렌더링한다 — 그러지 않으면 인쇄용으로 앱 UI를 숨길 때 인쇄물까지 사라진다.

PNG 저장 버튼은 같은 배치를 캔버스로 래스터화한다(`composite.ts`). 다운로드에는 비트맵이
필요해서 남겨둔 유일한 두 번째 경로이고, 겉모습은 `WorkspaceView`를 따라간다.

## 구조

```
src/
  lib/
    homography.ts   4점 DLT, 역행렬, 사각형 정렬, 정면 보정 워프
    detectSheet.ts  밝은 영역 검출 → 볼록껍질 → 4모서리 → 전체해상도 정밀화
    refineQuad.ts   변 직선 최소제곱 피팅 + 교점
    calibrate.ts    모서리 + 실측크기 → Calibration (안정성 검사 포함)
    geometry.ts     cm 공간 사각형 충돌·클램프·자리찾기
    cabinets.ts     캐비닛 규격, 픽셀 피치, 해상도 계산
    composite.ts    PNG 저장용 래스터 합성
    palette.ts      레이어 색(화면·인쇄 공용)
  state/store.ts    zustand 스토어 (단계, 보정, 레이어)
  components/       화면 3개 + 사이드 패널 + WorkspaceView(화면·인쇄 공용) + PrintView
```

복원, A4 방향 판별, 방향 오판 시 오차 회귀, 수평 보정의 거리 보존, 자리찾기 포화).
